## Decisions

The record restarts at 0001 with probatum. emsl's record is absorbed rather than continued: every decision it took that still holds lives inside one of these, amended where emsl was wrong, and emsl's own numbers stay in its history.

Each entry is one paragraph. It says what was decided, what emsl did instead where the two differ, and what the decision costs.

<br>

**0001 probatum replaces emsl rather than staying compatible with it.** probatum is emsl's repository renamed and released as 2.0.0, and where emsl simulated something a venue does not do, probatum's result moves rather than repeating it. A compatibility mode that kept emsl's numbers was possible and was rejected: it would be a second engine to test, and a way to reach a flattering number by accident. From 2.0.0 the simulator's behaviour is part of the API, so a public name, a keyword's meaning, a return type or a rule this record sets changes only in a major release, with a record saying what was wrong. The cost is that a result from emsl and one from probatum on the same bars can differ, and a reader has to look up why.

**0002 One sentence, four depths.** The whole API is one sentence: data, run on a venue, by a policy, gives a result. An array of weights, a Strategy, a Gymnasium environment and the caller's own loop around the Engine are four depths of one step, and all four return the same Result, so moving from an array to a strategy or an agent never changes what a number means. The venue is an argument of every verb, where emsl's `Market` handed the verbs out, and no verb takes a single venue setting as a keyword, so a setting has one place to be given and cannot arrive twice with two values. The cost is that changing one fee for one run means building a variant of the venue with `replace`.

**0003 Every run steps every bar.** Stops, limits, funding and liquidation depend on the path a position took, so every run steps every bar through one event loop, and a decision made at a bar's close fills at the next bar's open, never on the bar it saw. A vectorized backtest was rejected because it simulates an easier market than the real one. Speed comes from where the loop runs instead: an array run is stepped whole in Rust, a Strategy calls Python once per bar, and the batch steps thousands of accounts with the GIL released. The batch serves the Python verbs rather than being an API of its own, so nothing a user runs has to be compiled into the engine first. The cost is that a search over thousands of parameter sets pays for thousands of full runs, which the batch makes fast but never free.

**0004 Time is the bars that exist.** Every bar carries its open time in UTC nanoseconds, and a Data's clock is the set of times at which any of its instruments printed a bar, with nothing invented between them. A market that closes on Friday opens its next bar on Monday: positions carry across the gap, indicators run straight across it, and an order decided at Friday's close fills at Monday's open. Intraday rows sit whole intervals apart, so instruments whose bars open at different minutes are refused rather than interleaved, and a daily bar is placed on its own date. Annualisation counts the clock's own rows per year of its span and is never assumed, where emsl read it from the median gap and fell back to 365 on bare arrays. The cost is that bars without times cannot run, so a Data built from arrays needs `time=`.

**0005 A Data owns its bars.** A Data is a universe: instruments keyed by venue, market and symbol, read with singular names when there is one and plural ones when there are several. It copies its input once, bar-major, and every view of it is read-only, so no later edit can change the bars under an unchanged fingerprint; that fingerprint, 128 bits over everything a run reads, travels into every result. An instrument enters at its first bar and may leave at a delisting time. A Data saves to a file the user names and loads back under the same fingerprint, and probatum keeps no store of its own. The cost is one full copy of the bars per Data, and a universe that is only ever the user's own list of symbols.

**0006 Coarser bars and outside series arrive when they were known.** A decision at a bar's close may use only what was known by that bar's end, and data on another clock is where bar research most often breaks that. `resample` builds coarser bars from whole multiples of the interval, aligned as the venues align them, and drops a coarse bar the data does not cover to its end. `asof` puts each value from another clock on the row by whose end it was known, never on the row whose open time matches it, since that join hands an hourly decision the close of a day still trading. Together they give decisions on a coarse clock with execution on finer bars, without a second clock in the engine. The cost is that an outside series joined some other way is invisible to probatum, so it cannot be refused.

**0007 The boundary refuses what it cannot simulate.** Every argument is checked where it enters, and a value the engine cannot simulate is refused with the argument's name, the value that arrived and the fix, rather than repaired: a non-finite or out-of-range setting, a price at or below zero, a bar whose high and low do not contain its open and close, a negative volume, a row with only some values present, an order that can never fill. Every path into a venue setting, from a preset file to per-environment cost ranges, passes one validator, so no path admits a value another refuses. The cost is that a feed with one bad bar has to be cleaned before it runs.

**0008 One account, two wallets.** An account keeps the two wallets venues keep. The spot wallet holds cash and spot holdings, never borrows, clamps a buy to its cash and a sell to its holding, so it cannot short, and is never liquidated. The margin wallet backs every perpetual in cross margin, so one balance carries them all and a liquidation closes them all together. Cash crosses between the wallets only by a transfer, decided at a close, applied at the next bar's start and clamped so the margin left still covers the cap. Equity is the sum of both, and an account whose equity reaches zero is terminal. Isolated and unified margin were left out, each a different liquidation rule. The cost is that a carry trade moves its own collateral, as it would on the venue.

**0009 A size's unit is its verb.** `buy` and `sell` take base units, or contracts on an inverse instrument, `buy_value` and `sell_value` take the quote currency, and `target` takes signed weights of account equity, so a size is never read in a unit its caller did not mean. `target` is the main verb for portfolios, models and agents: it turns weights into legs at the close, places every reducing leg before every growing one so a rebalance is funded by its own sales, rounds each leg toward zero to the lot, skips one below the tolerance or the minimum notional, and records what the fills left between the weights asked for and the weights held. An array run gives every position the barriers `labels` uses, so a model trades the way its labels were made. The cost is three verbs where a keyword could have chosen the unit.

**0010 Orders keep emsl's semantics, on a named instrument.** Every order type emsl had stays, now on a named instrument, with the rules it settled: time in force, all-or-nothing judged after every clamp, a stop that cannot fill has not triggered and is consumed only by what it filled, an order retires at a size it can no longer fill, ids are unique for the engine's life, `replace` keeps an order's id and a refused one restores the original in its own slot, and `max_open_orders` bounds the pending queue as well as the book. `reduce_only` now works on every order type, where emsl had it on stops alone; a `post_only` limit the first bar opens through is cancelled, where emsl filled it as a taker; and `bracket` places two exits as one OCO pair. Every placing verb returns an `Order` handle, refused ones included with their reason, where emsl returned `None`. The cost is a handle object per order where an integer used to do.

**0011 A resting limit is on the book.** A limit is a taker only on the first bar after its placement, when that bar opens at or through it; once it has rested through a bar it is on the book, and it fills as a maker whatever later bars do. emsl charged the taker rate to any limit a bar opened through, rested or not. A limit that would trade against the account's own resting limit is refused, as venues refuse it, which removes the straddle of two limits both filling as makers on one wide bar. Resting orders across every instrument share one slot table and resolve in slot order, so when a clamp binds, the order that gets the room is fixed. The cost is that a strategy built on crossing its own orders sees them refused.

**0012 What a bar cannot show is decided by one setting.** A bar gives four prices and no order between them, so some outcomes cannot be read from it: a stop and a take-profit both reached, a take-profit and the liquidation trigger both reached, how much of the bar came after a fill inside it, a funding event stamped inside the bar, several instruments each at their worst. One venue setting, `intrabar`, decides all of them alike, and pessimistic is the default everywhere: the worse of two exits fills first, as emsl decided, with only exits reordered; a take-profit on a liquidating bar is held back; an order that can only reduce meets a position a fill inside the bar opened or flipped on the part of the bar after that fill, which reaches an extreme the bar may have printed before the fill where it works against the position, as the check does, and where it favours the position only under the optimistic setting; and every instrument reaches its worst price at once. Optimistic decides each event the other way, and random draws each from a seeded stream, for training only, so an agent cannot learn a fixed tie-break. The cost is a result that depends on a setting the user may not know is there, so every result says which way it ran.

**0013 A fill is what a venue would give.** A taker fills at the next open moved against its side by half the spread, the slippage and the impact, and is held inside the bar's range, so no fill prices where the bar never traded. Each rule of the fill model is a choice in the venue rather than a constant: touch or through for limits, a trailing window, a liquidity budget per bar shared by every order, a spread estimated from the bars, square-root impact in the fill's share of the trailing volume, fees, and the lot, tick and minimum notional. emsl capped each order at a share of the volume of the bar it filled on, which a split order multiplied. Presets take the realistic option in every row, and a hand-built venue starts from the plain one. The cost is that a preset's slippage and impact are a starting calibration, not a measurement of anyone's costs.

**0014 A flip realizes through zero, and each fee is paid once.** A fill that crosses zero closes the old side at its average entry and opens the remainder at the fill price, and a same-side add volume-weights the entry. Cash moves only with the position, so a fill too small to move the position moves no cash and no fee. A round trip carries its entry fee and its exit fee exactly once, so on a run that ends flat with no liquidation charge, the round trips' net PnL equals the change in equity. Money is float64, updated in event order with plain arithmetic, so any amount can be followed by hand. The cost is that dust below the threshold is dropped rather than tracked.

**0015 Margin is shared, and an account over its cap may only shrink.** In cross margin the sum of each perpetual's notional over its tier's maximum leverage may not exceed margin equity, measured before the fill's own fee as emsl measured it, except that a flip's new side is sized after the fee on the side it closes, with the other legs marked at the same fraction of their bars as the fill sits at on its own. A growing fill is clamped to what the cap allows, and the clamp is logged. An account over the cap because equity fell is never force-reduced, only kept from growing, and one at or below zero equity may only shrink. Maintenance follows the venues' tier tables, by notional or by contracts, and a table whose cumulative amounts break continuity is refused. The cost is tier tables that are dated data, kept current by hand.

**0016 Inverse contracts are linear in the reciprocal of the price.** An inverse perpetual is quoted in dollars and settled in its coin. Every quantity the account counts on it (profit, notional, fees, funding and the requirement) is linear in `1 / p`, so the closed forms and the path solver for linear contracts carry over in the reciprocal of the price. Each settles in its own coin and an account has one settlement asset, so an inverse account holds that one perpetual, and its results are in the coin, as the venue keeps them, with equity valued in dollars beside them. The cost is that a book of several coin-margined contracts runs as one account per coin.

**0017 A liquidation is a price on the bar's path.** A bar whose prices reach the trigger liquidates the account on that bar. The bar's own trade prices decide, rather than a mark price, which exchange-router does not serve as history, and they err toward liquidating. Every perpetual held moves along one synchronous adverse path: a gap segment from its last mark to its open, and a bar segment from its open to its adverse extreme. Equity is linear along it and the requirement piecewise linear, so the first crossing is solved exactly rather than searched for, and the bars are clipped where the account leaves the market, so no order fills beyond that point. emsl tested one instrument with no maintenance; the path extends the same idea to several instruments and to the venues' tiers. The cost is that a position within a wick of its trigger is liquidated where a venue marking on a smoother price might have kept it.

**0018 No account ends a bar owing money.** A forced close leaves the margin wallet at exactly zero, and whatever it still held, positive or negative, is booked as the liquidation charge: what the venue's clearance fee takes, or what the venue absorbs. Every reducing fill passes a margin bound as it lands, so no order of fills inside a bar can realize past the point where the margin runs out. A fill the bound lifts stays inside its bar and short of its position's average entry, and the part the bar cannot hold is booked as a negative charge, where emsl lifted the fill past the bar's high. A liquidation cancels every resting perpetual order. The cost is a negative liquidation charge, a number with no line on a venue's statement, standing in for the insurance fund.

**0019 Each venue liquidates in its own way.** The forced close is a choice in the venue. Takeover, which Binance, Bybit and OKX use and every hand-built venue starts from, closes every leg at the clip point and books what remains as the liquidation charge. Book then backstop, Hyperliquid's, sells every leg into the book from its trigger as a taker and leaves the trader what remains, falling back to takeover when the path also reaches the backstop level or the sale's own costs would cross it, since the bar cannot show that the sale finished first. One generic rule was rejected because the two leave a trader very different amounts. The cost is a second liquidation model held to the reference.

**0020 Funding is charged when the venue charges it.** Funding events are read at their real times from the venue's history, with each symbol's interval as it changed. A row of the clock owns the events stamped after its open and up to its end, and they are charged at its closes after the liquidation check, so an account liquidated before a stamp pays nothing for it, and a debit that takes the account to its trigger at the closes liquidates it there. An event stamped between rows, across a closure or a hole in the data, is charged at the next row's start, before its gap, on the positions that carried through it, so no decision sees a rate published after it. emsl charged funding every n bars from the start of the array, and before the liquidation check, so a payment not yet made could liquidate an account at the bar's low. The cost is funding priced at the close rather than at the venue's mark.

**0021 The same numbers on every machine.** A run gives the same bits on every supported platform. Rust leaves `ln`, `exp` and `powf` free to differ by platform, so every transcendental function goes through `libm`, integer powers are written as products, sums run in a fixed instrument order, and every random draw comes from a named stream derived from the run's seed. Compensated summation is kept for reported totals, so cash and positions stay plain arithmetic in event order. The cost is that the engine cannot use the platform's faster maths, nor reorder a sum for speed.

**0022 A run records its ledger, its fills and its orders.** A run records a ledger with one row per bar from the opening balance on, a fill log carrying each fill's reference price and every cost measured against it, and an order log with every order's events and the reason for each, where emsl kept a trade row per closed portion and shrank a clamped fill without a word. The ledger identity, the change in equity equal to price PnL less every cost, holds within an error bound derived from the magnitudes involved, and each term in it is computed on its own, so none is a residual that would make the check pass by construction. Recording levels trade detail for memory, and `backtest` refuses the level that keeps nothing. The cost is memory: a full ledger of a large universe runs to hundreds of megabytes.

**0023 A trade is a round trip.** A trade is a maximal run of one sign on one instrument: it opens when a position leaves zero and ends when it returns to zero or flips, and resizing inside it does not end it, so `num_trades` counts decisions rather than fills. Its net PnL is after its fees and the funding it paid while open, and a round trip still open at the end is reported, marked at the last close and flagged, where emsl left an open position out of every trade metric. Its best and worst excursions are bounds over the part of each bar the trade was in, so neither overstates. The cost is that a strategy that scales in and out reads as one long trade.

**0024 `backtest` accepts anything that decides, read one way.** `backtest` dispatches in one fixed order (a table, an array, a Strategy, a Stable-Baselines3 model, a torch module, any other callable), so no input is ever read two ways, and a class, or an object that only fits, is refused with the fix. A policy is a prototype: every run, trial, validation window and cost level deep-copies it before `init`, and the copy is `result.policy`, so two calls on one instance start alike and a chart draws the arrays the fills were decided on. emsl's cost sweep restored attributes by hand and missed what was mutated in place. The cost is a deep copy per run, which a policy holding a large model pays every time.

**0025 A Strategy sees only the past and its own account.** A Strategy's `next(bar, account)` reads typed views of the current bar and of the account, and `bar.history` is its only window onto earlier bars, so logic computed inside `next` cannot read a later one. The account exposes the strategy's own orders, round trips and equity curve, so a strategy can size on its own record. `init` runs once over the whole series; `next` is not called before a declared warm-up, while the bars before it still advance and fill resting orders; parameters are the constructor's arguments; and `on_inherit` hands a position across a validation seam. emsl passed a state dict and the engine itself. The cost is Python on every bar for any logic that lives in `next`.

**0026 One Result and one Study.** Every run returns the same `Result`, whatever decided it: returns and equity as arrays, and tables exposed through the Arrow C stream interface, so polars, pyarrow and DuckDB read them without probatum importing any of them. On disk a Result is a directory of open formats with a schema version, and its provenance records the data's fingerprint, the venue, the seeds and every package version the run loaded. A `Study` is a set of Results that keeps every row's returns, which the statistics across a search need and emsl discarded, and `combine` adds Results from different venues into one book. The cost is a returns matrix that grows with trials and bars, bounded by `keep=`.

**0027 Every assumption is graded.** Every run lists each modelling choice it made in one table: its value, its source, a grade (as the venue does it, simplified, or optimistic), the direction of its error when simplified, and what it cost in that run, read from the ledger. A choice switched off is listed as off, never left out, and a result that ran with anything graded optimistic says so in its summary line. A fill or an order can be explained one at a time, and every report sets the strategy beside holding cash, buying and holding, and the same policy on a frictionless venue. Re-running a policy with each assumption moved was rejected, since the table already names and prices every choice. The cost is a table the user has to read.

**0028 Venue presets are dated data.** A preset is a TOML file with a published schema, dated, citing the venue's own documents, and validated when it loads, so a new venue or a corrected fee table is a data change rather than a change to Rust. Each preset carries its own venue's rules, not one venue's copied to the others, and the frictionless preset separates an edge from what the venue took. The cost is that presets go stale as venues change their tables, and nothing checks them against the live venue.

**0029 One error tree.** Every error probatum raises derives from `ProbatumError` and from the built-in it means, so `except ValueError` still catches a bad value and a caller can also catch probatum's errors alone. Each names the argument, the value that arrived and the fix. Every warning is a `ProbatumWarning`, and long work is logged to the `probatum` logger rather than printed. The cost is a set of classes to keep stable across releases.

**0030 The statistics stay finite and rank monotonically.** The statistics use fixed conventions: the sample deviation for volatility and the Sharpe, the population deviation for Sortino's downside, and square-root annualisation. They stay finite on any run, so one degenerate run cannot poison a search: a zero denominator ranks at infinity for a positive reward and at zero otherwise, a losing run's Calmar is scaled by its drawdown rather than divided by it, drawdown is capped at a total loss, and a tail is taken by rank. Trade statistics are net of costs, and a metric that reads a run's bars checks it was given the same bars. A plain return series must state `periods_per_year`, which has no default anywhere. The cost is conventions that differ from some other tools, written down so a reader can convert.

**0031 Every interval names its method.** The Sharpe's variance is the delta-method variance with a Newey-West long-run covariance, floored at its lag-zero value, so autocorrelation can widen an interval and never narrow it; it replaces emsl's effective sample at the first lag, which stays available by name. Each headline statistic has one interval, and its method is named: the delta method for the Sharpe, a stationary block bootstrap for statistics with a population value, a range of resampled histories for drawdown, and a bootstrap of round trips for trade statistics. A sample that cannot support an interval gets none, two Sharpes on the same bars are compared by their difference, and alpha and beta are estimated against a benchmark. The cost is that intervals are computed when first read, never inside a search, so a search ranks on point estimates.

**0032 A search never sees its holdout.** `search` scores every trial on one run over the bars before the holdout, which is always the tail; `evaluate_holdout` runs the winner there once and counts the look. Every trial counts as a look, failed ones included, and `min_trades` fails a trial with too few round trips. The deflated Sharpe takes a random-search null over the same space and bars, because a TPE search concentrates its trials and cannot supply its own spread. Samplers are built with every behaviour-changing argument explicit, workers start with `spawn` and rebuild the engine rather than receive one, a policy's decisions are checked for causality by cutting the bars, and a search over arrays steps its trials together in the batch. The cost is a holdout that can be spent once, with every further look counted.

**0033 A search is judged across all its trials.** A search reports the deflated Sharpe against every trial and against the effective number of trials, the probability of backtest overfitting, White's Reality Check and Hansen's SPA against a stated benchmark, and the minimum backtest length. The overfitting probability is computed by combinatorially symmetric cross-validation on the returns each trial earned in its own run, never by re-simulating recombined blocks, which emsl rightly refused for a path-dependent engine, so it ranks only on statistics that do not depend on order. These are tests on random or grid searches, labelled descriptive on an adaptive one. The cost is that every trial's returns must be kept.

**0034 A validation is one run.** A walk-forward is one engine pass with a composite policy that hands each bar to the window that owns it, so the account carries across seams and every warm-up sees the bars before its window; stitching separate runs would reset the account and invent trades at every seam. Each window is scored on the run that happened. A model is refitted from a fresh estimator for every window and trades through the same engine with its labels' barriers. Seams are explicit: resting orders are cancelled and the next window inherits the position, or each seam flattens, where emsl left resting orders behind with nothing owning them. The cost is windows that cannot run in parallel.

**0035 Splitters purge by label end.** The splitters work on rows in the time-major form an estimator sees, each with its label's end, and remove a training row whose label overlaps a test span on either side, then embargo the bars after it. They meet scikit-learn's splitter contract without importing it. A Strategy has no labels, so each contiguous piece of a training span is its own run, ending at its last bar, and its embargo is at least its warm-up. The cost is that a splitter built for one series refuses a fold's rows, so it is built once per series.

**0036 Labels are trades through the same fill model.** A label is what a trade of a stated notional, entered at the next open, would have returned through the same fill model as a backtest, net of fees, funding, spread, slippage and impact, with optional barriers. A short label is computed on its own rather than as the long one's negative, since both pay costs and funding changes sign. A label whose horizon runs past the data is censored even when a barrier was hit first, so censoring never depends on the outcome, and every label carries its end and its average uniqueness. The cost is that labels run the engine, slower than returns read off the closes.

**0037 Indicators run over each instrument's own bars.** `probatum.ta` keeps emsl's closed set of indicators and states each one's convention where implementations differ. Every function returns one value per bar with the warm-up as NaN, never a shorter array; crossings return booleans that are false during the warm-up; and a shift pads rather than wraps. Each instrument's indicators run over the bars it printed and skip the rows where it did not, so a closure neither breaks nor restarts them. The recursive smoothers are vectorized between gaps, which keeps them within rounding of a per-bar loop rather than bit-identical to it. The cost is that an indicator outside the set is the user's to write.

**0038 The environment shows the agent its account.** `probatum.env` is a Gymnasium vector environment over the Rust batch, with all three of Gymnasium's autoreset modes and `NEXT_STEP`, Gymnasium's own default, as its default, where emsl had `SAME_STEP` alone; the Stable-Baselines3 adapter switches to `SAME_STEP`, which SB3 expects. Every observation carries the account (weights, unrealized PnL and margin), so an agent sees what it holds, and actions are normalised by gross exposure, so an untrained policy over many instruments cannot ask for many times its leverage. Order actions are decoded in Rust, which ends emsl's market-order-only batch, the reward is floored so a liquidation is a large finite penalty, and costs can be drawn per environment. The cost is an observation larger than the market data alone.

**0039 An agent carries the spec it trained with.** An agent is judged fairly only if it sees in a backtest what it saw in training, so `probatum.env` records its keywords as a versioned JSON spec, with any normalisation statistics, the training span's fingerprint and the venue, and `backtest` rebuilds the observation from it. A custom function is never pickled: the spec records its name, its width, a hash of its source and its output on a dataset shipped with the package, and a function passed again that gives a different output is refused. The cost is that a custom feature function has to be passed again at every backtest.

**0040 One output buffer, and a path to the GPU.** The batch fills one writable float32 buffer in place, and every framework reaches it by its own zero-copy path, so none is special inside the engine; observations are handed out as copies by default, so a replay buffer stays safe. `TensorEnv` moves them to a device through pinned double buffers, and its resident mode copies the features to the device once and gathers each window there, so only offsets and account values cross the link each step. A single environment fills the same buffer, which replaces emsl's read-only view onto the candle buffer, since an observation now carries the account as well as the bars. Engines and environments clone, so a fork for planning repeats its original exactly. The cost is a second code path for the device, held bit for bit to the host's.

**0041 Reports are static figures over the Result.** Reports and figures are matplotlib figures with a pinned font, embedded as SVG in one HTML file with no JavaScript. They plot fields of the Result and compute nothing, so they can be redesigned without moving a number, and they are checked by the data they plot rather than by their pixels. The cost is plainer pictures than an interactive dashboard would give.

**0042 The interactive chart is kept as emsl built it.** The candle chart stays as emsl built it, for inspecting trades, and stops growing. It is precomputed in Python and self-contained in one HTML document with its renderer vendored, so a saved chart works offline; it draws arrays that arrive computed and knows no indicator names; Python and JavaScript meet at one spec, with the JavaScript computing geometry and never policy; plotting is never declared inside a strategy; and a series is aligned by position, a NaN breaks the line, and a bare array overlays the candles unless it would flatten them. The renderer's attribution is shown, as its licence asks. The cost is that new work on pictures goes to the static figures instead.

**0043 The maths is verified inside the repository.** There is no reviewer and no check against a live venue, so the maths is proven in the repository: every rule is written in the Specification with an equation and a worked example before it is coded, and every worked example is a test. A reference simulator, written from the Specification and never from the engine, finds the liquidation path's crossings by bisection where the engine solves them in closed form, and the two are compared on every ledger column over random cases, with tolerances derived from the magnitudes involved. Tests are named as the claims they prove and run over a deliberately awkward fake market at every depth, and every code block in the documentation is executed. The cost is a second simulator maintained beside the engine.

**0044 The core depends on numpy alone.** Everything else is imported when used, so a backtest never loads Gymnasium; three extras cover probatum's own optional features, and frameworks the user brings, such as torch, are never extras, because an extra would install a build over the one the user chose. Python versions follow Scientific Python's SPEC 0, dependencies carry no upper bounds, and wheels ship for Linux, macOS on Apple silicon and Windows, with no free-threaded build in 2.0.0. The package declares `MIT AND Apache-2.0`, because the wheel ships the chart's renderer. The cost is that an older Python or an Intel Mac is not supported.
