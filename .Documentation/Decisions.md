## Decisions

The record restarts at 0001 with probatum. emsl's record is absorbed rather than continued: every decision it took that still holds lives inside one of these, amended where emsl was wrong, and emsl's own numbers stay in its history.

Each entry is one paragraph. It says what was decided, what emsl did instead where the two differ, and what the decision costs.

<br>

**0001 probatum replaces emsl rather than staying compatible with it.** probatum is emsl's repository renamed and released as 2.0.0, and where emsl simulated something a venue does not do, probatum's result moves rather than repeating it. A compatibility mode that kept emsl's numbers was possible and was rejected: it would be a second engine to test, and a way to reach a flattering number by accident. From 2.0.0 the simulator's behaviour is part of the API, so a public name, a keyword's meaning, a return type or a rule this record sets changes only in a major release, with a record saying what was wrong. The cost is that a result from emsl and one from probatum on the same bars can differ, and a reader has to look up why.

**0002 One sentence, four depths.** The whole API is one sentence: data, run on a venue, by a policy, gives a result. An array of weights, a Strategy, a Gymnasium environment and the caller's own loop around the Engine are four depths of one step, and all four return the same Result, so moving from an array to a strategy or an agent never changes what a number means. The venue is an argument of every verb, where emsl's `Market` handed the verbs out, and no verb takes a single venue setting as a keyword, so a setting has one place to be given and cannot arrive twice with two values. The cost is that changing one fee for one run means building a variant of the venue with `replace`.

**0003 Every run steps every bar.** Stops, limits, funding and liquidation depend on the path a position took, so every run steps every bar through one event loop, and a decision made at a bar's close fills at the next bar's open, never on the bar it saw. A vectorized backtest was rejected because it simulates an easier market than the real one. Speed comes from where the loop runs instead: an array run is stepped whole in Rust, a Strategy calls Python once per bar, and the batch steps thousands of accounts with the GIL released. The batch serves the Python verbs rather than being an API of its own, so nothing a user runs has to be compiled into the engine first. The cost is that a search over thousands of parameter sets pays for thousands of full runs, which the batch makes fast but never free.

**0004 Time is the bars that exist.** Every bar carries its open time in UTC nanoseconds, and a Data's clock is the set of times at which any of its instruments printed a bar, with nothing invented between them. A market that closes on Friday opens its next bar on Monday: positions carry across the gap, indicators run straight across it, and an order decided at Friday's close fills at Monday's open. Intraday rows sit whole intervals apart, so instruments whose bars open at different minutes are refused rather than interleaved, and a daily bar is placed on its own date. Annualisation counts the clock's own rows per year of its span and is never assumed, where emsl read it from the median gap and fell back to 365 on bare arrays. The cost is that bars without times cannot run, so a Data built from arrays needs `time=`.

**0005 A Data owns its bars.** A Data is a universe: instruments keyed by venue, market and symbol, read with singular names when there is one and plural ones when there are several. It copies its input once, bar-major, and every view of it is read-only, so no later edit can change the bars under an unchanged fingerprint; that fingerprint, 128 bits over everything a run reads, travels into every result. An instrument enters at its first bar and may leave at a delisting time, which the venue's own table for it gives, since the router serves none. A Data saves to a directory the user names, as Arrow files, and loads back under the same fingerprint, and probatum keeps no store of its own. The cost is one full copy of the bars per Data, and a universe that is only ever the user's own list of symbols.

**0006 Coarser bars and outside series arrive when they were known.** A decision at a bar's close may use only what was known by that bar's end, and data on another clock is where bar research most often breaks that. `resample` builds coarser bars from whole multiples of the interval, aligned as the venues align them, and drops a coarse bar the data does not cover to its end. `asof` puts each value from another clock on the row by whose end it was known, never on the row whose open time matches it, since that join hands an hourly decision the close of a day still trading. Together they give decisions on a coarse clock with execution on finer bars, without a second clock in the engine. The cost is that an outside series joined some other way is invisible to probatum, so it cannot be refused.

**0007 The boundary refuses what it cannot simulate.** Every argument is checked where it enters, and a value the engine cannot simulate is refused with the argument's name, the value that arrived and the fix, rather than repaired: a non-finite or out-of-range setting, a price at or below zero, a bar whose high and low do not contain its open and close, a negative volume, a row with only some values present, an order that can never fill. The one value it leaves to Python is an integer no float holds, which raises `OverflowError` where it is converted, as `float()` raises it. Every path into a venue setting, from a preset file to per-environment cost ranges, passes one validator, so no path admits a value another refuses. The cost is that a feed with one bad bar has to be cleaned before it runs.

**0008 One account, two wallets.** An account keeps the two wallets venues keep. The spot wallet holds cash and spot holdings, never borrows, clamps a buy to its cash and a sell to its holding, so it cannot short, and is never liquidated. The margin wallet backs every perpetual in cross margin, so one balance carries them all and a liquidation closes them all together. Cash crosses between the wallets only by a transfer, decided at a close, applied at the next bar's start and clamped so the margin left still covers the cap. Equity is the sum of both, and an account whose equity reaches zero is terminal. Isolated and unified margin were left out, each a different liquidation rule. The cost is that a carry trade moves its own collateral, as it would on the venue.

**0009 A size's unit is its verb.** `buy` and `sell` take base units, or contracts on an inverse instrument, `buy_value` and `sell_value` take the quote currency, and `target` takes signed weights of account equity, so a size is never read in a unit its caller did not mean. `target` is the main verb for portfolios, models and agents: it turns weights into legs at the close, places every reducing leg before every growing one so a rebalance is funded by its own sales, rounds each leg toward zero to the lot, skips one below the tolerance or the minimum notional, and records what the fills left between the weights asked for and the weights held. An array run gives every position the barriers `labels` uses, so a model trades the way its labels were made, each placed at the close its entry filled on, from the average entry it filled at, as a Strategy would place it, and a barrier's fill holds its instrument flat until its weight returns to zero or changes sign, so a row still asking for the position does not buy it straight back. The cost is three verbs where a keyword could have chosen the unit, a barrier that misses the bar its entry filled on, and an array of one weight throughout that never enters again after its first barrier.

**0010 Orders keep emsl's semantics, on a named instrument.** Every order type emsl had stays, now on a named instrument, with the rules it settled: time in force, all-or-nothing judged after every clamp, a stop that cannot fill has not triggered and is consumed only by what it filled, an order retires at a size it can no longer fill, ids are unique for the engine's life, `replace` keeps an order's id and a refused one restores the original in its own slot, and `max_open_orders` bounds the pending queue as well as the book. `reduce_only` now works on every order type, where emsl had it on stops alone; a `post_only` limit the first bar opens through is cancelled, where emsl filled it as a taker; and `bracket` places two exits as one OCO pair. Every placing verb returns an `Order` handle, refused ones included with their reason, where emsl returned `None`. The cost is a handle object per order where an integer used to do.

**0011 A resting limit is on the book.** A limit is a taker only on the first bar after its placement, when that bar opens at or through it; once it has rested through a bar it is on the book, and it fills as a maker whatever later bars do. emsl charged the taker rate to any limit a bar opened through, rested or not. A limit that would trade against the account's own resting limit is refused, as venues refuse it, which removes the straddle of two limits both filling as makers on one wide bar. Resting orders across every instrument share one slot table and resolve in slot order, so when a clamp binds, the order that gets the room is fixed. The cost is that a strategy built on crossing its own orders sees them refused.

**0012 What a bar cannot show is decided by one setting.** A bar gives four prices and no order between them, so some outcomes cannot be read from it: a stop and a take-profit both reached, a take-profit and the liquidation trigger both reached, how much of the bar came after a fill inside it, a funding event stamped inside the bar, several instruments each at their worst, a sale on the book and the backstop level both reached. One venue setting, `intrabar`, decides all of them alike, and pessimistic is the default everywhere: the worse of two exits fills first, as emsl decided, with only exits reordered; a take-profit on a liquidating bar is held back; an order that can only reduce meets a position a fill inside the bar opened or flipped on the part of the bar after that fill, which reaches an extreme the bar may have printed before the fill where it works against the position, as the check does, and where it favours the position only under the optimistic setting; every instrument reaches its worst price at once; and the backstop takes over a sale whose path reaches its level. Optimistic decides each event the other way, and random draws each from a seeded stream, for training only, so an agent cannot learn a fixed tie-break. The cost is a result that depends on a setting the user may not know is there, so every result says which way it ran.

**0013 A fill is what a venue would give.** A taker fills at its reference, the next open or a stop's trigger where that is worse, moved against its side by half the spread, the slippage and the impact, and is held inside the bar's range, so no fill prices where the bar never traded. Each rule of the fill model is a choice in the venue rather than a constant: touch or through for limits, a trailing window, a liquidity budget per bar shared by every order, a spread estimated from the bars, square-root impact in the fill's share of the trailing volume, fees, and the lot, tick and minimum notional. emsl capped each order at a share of the volume of the bar it filled on, which a split order multiplied. Presets take the realistic option in every row, and a hand-built venue starts from the plain one. The cost is that a preset's slippage and impact are a starting calibration, not a measurement of anyone's costs.

**0014 A flip realizes through zero, and each fee is paid once.** A fill that crosses zero closes the old side at its average entry and opens the remainder at the fill price, and a same-side add volume-weights the entry. Cash moves only with the position, so a fill too small to move the position moves no cash and no fee. A round trip carries its entry fee and its exit fee exactly once, so on a run that ends flat with no liquidation charge, the round trips' net PnL equals the change in equity. Money is float64, updated in event order with plain arithmetic, so any amount can be followed by hand. The cost is that dust below the threshold is dropped rather than tracked.

**0015 Margin is shared, and an account over its cap may only shrink.** In cross margin the sum of each perpetual's notional over its tier's maximum leverage may not exceed margin equity, measured before the fill's own fee as emsl measured it, except that a flip's new side is sized after the fee on the side it closes, with the other legs marked at the same fraction of their bars as the fill sits at on its own. A growing fill is clamped to what the cap allows, and the clamp is logged. An account over the cap because equity fell is never force-reduced, only kept from growing, and one at or below zero equity may only shrink. Maintenance follows the venues' tier tables, by notional or by contracts, and a table whose cumulative amounts break continuity is refused. The cost is tier tables that are dated data, kept current by hand.

**0016 Inverse contracts are linear in the reciprocal of the price.** An inverse perpetual is quoted in dollars and settled in its coin. Every quantity the account counts on it (profit, notional, fees, funding and the requirement) is linear in `1 / p`, so the closed forms and the path solver for linear contracts carry over in the reciprocal of the price, and the engine runs an inverse account as a linear one there. A taker's spread, slippage and impact move `1 / p` as well, so each costs its rate of the coin notional at the reference, as a fee costs its rate of the notional at the fill; moved on the dollar price instead, a rate `c` would cost `c / (1 + c)` of it on a buy and `c / (1 - c)` on a sale, and need a formula of its own. Each settles in its own coin and an account has one settlement asset, so an inverse account holds that one perpetual, and its results are in the coin, as the venue keeps them, with equity valued in dollars beside them. The cost is that a book of several coin-margined contracts runs as one account per coin.

**0017 A liquidation is a price on the bar's path.** A bar whose prices reach the trigger liquidates the account on that bar. The bar's own trade prices decide, rather than a mark price, which exchange-router does not serve as history, and they err toward liquidating. Every perpetual held moves along one synchronous adverse path: a gap segment from its last mark to its open, and a bar segment from its open to its adverse extreme. Equity is linear along it and the requirement piecewise linear, so the first crossing is solved exactly rather than searched for, and the bars are clipped where the account leaves the market, so no order fills beyond that point. emsl tested one instrument with no maintenance; the path extends the same idea to several instruments and to the venues' tiers. The cost is that a position within a wick of its trigger is liquidated where a venue marking on a smoother price might have kept it.

**0018 No account ends a bar owing money.** A takeover leaves the margin wallet at exactly zero, and whatever it still held, positive or negative, is booked as the liquidation charge: what the venue's clearance fee takes, or what the venue absorbs. Every reducing fill passes a margin bound as it lands, so no order of fills inside a bar can realize past the point where the margin runs out. A fill the bound lifts stays inside its bar and short of its position's average entry, and the part the bar cannot hold is booked as a negative charge, where emsl lifted the fill past the bar's high. A liquidation cancels every resting perpetual order. The cost is a negative liquidation charge, a number with no line on a venue's statement, standing in for the insurance fund.

**0019 Each venue liquidates in its own way.** The forced close is a choice in the venue. Takeover, which Binance, Bybit and OKX use and every hand-built venue starts from, closes every leg at the clip point and books what remains as the liquidation charge. Book then backstop, Hyperliquid's, sells every leg into the book from its trigger as a taker and leaves the trader what remains. It falls back to takeover when the sale would leave the trader below the backstop level, and when the path also reaches that level, since the bar cannot show that the sale finished first; the optimistic setting has it finish first (ADR 0012). One generic rule was rejected because the two leave a trader very different amounts. The cost is a second liquidation model held to the reference.

**0020 Funding is charged when the venue charges it.** Funding events are read at their real times from the venue's history, with each symbol's interval as it changed. A row of the clock owns the events stamped after its open and up to its end, and they are charged at its closes after the liquidation check, so an account liquidated before a stamp pays nothing for it, and a debit that takes the account to its trigger at the closes liquidates it there. An event stamped between rows, across a closure or a hole in the data, is charged at the next row's start, before its gap, on the positions that carried through it, so no decision sees a rate published after it. emsl charged funding every n bars from the start of the array, and before the liquidation check, so a payment not yet made could liquidate an account at the bar's low. The cost is funding priced at the close rather than at the venue's mark.

**0021 The same numbers on every machine.** A run gives the same bits on every supported platform. Rust leaves `ln`, `exp` and `powf` free to differ by platform, so every transcendental function goes through `libm`, integer powers are written as products, sums run in a fixed instrument order, and every random draw comes from a named stream derived from the run's seed. A statistic's resampling draws from a stream named for it and seeded by a digest of the values it resamples, so an interval is the same on every read and in every process, and needs no seed its run never took. Compensated summation is kept for reported totals, so cash and positions stay plain arithmetic in event order. The cost is that the engine cannot use the platform's faster maths, nor reorder a sum for speed.

**0022 A run records its ledger, its fills and its orders.** A run records a ledger with one row per bar from the opening balance on, its holdings with one row per bar and instrument, each with what that instrument made since the first row, a fill log carrying each fill's reference price, every cost measured against it and what the margin bound lifted and paid in, and an order log with every order's events and the reason for each, where emsl kept a trade row per closed portion and shrank a clamped fill without a word. A clamp's reason names the rule that held the fill, and an order's placement records the side, size and price it asked, so the log says why a fill came out smaller than its order. Each is a table in which a value the record does not have is missing rather than a number that stands for none. The ledger identity, the change in equity equal to price PnL less every cost, holds within an error bound derived from the magnitudes involved, and each term in it is computed on its own, so none is a residual that would make the check pass by construction. Recording levels trade detail for memory: `full` keeps all of it, and `account` keeps the ledger and the round trips with no holdings, fill log or order log, its statistics the full level's to the bit, since they read only the equity, the closed round trips and the engine's own counts; a search's trials run together in Rust keep only what their statistics read, and `backtest` refuses the level that keeps nothing. The cost is memory: a full ledger of a large universe runs to hundreds of megabytes, its holdings repeating a bar, a time and a name on every row.

**0023 A trade is a round trip.** A trade is a maximal run of one sign on one instrument: it opens when a position leaves zero and ends when it returns to zero or flips, and resizing inside it does not end it, so `num_trades` counts decisions rather than fills. Its net PnL is after its fees and the funding it paid while open, and a round trip still open at the end is reported, marked at the last close and flagged, where emsl left an open position out of every trade metric. Its best and worst excursions are bounds over the part of each bar the trade was in, so neither overstates. The cost is that a strategy that scales in and out reads as one long trade.

**0024 `backtest` accepts anything that decides, read one way.** `backtest` dispatches in one fixed order (a table, an array, a Strategy, a Stable-Baselines3 model, a torch module, any other callable), so no input is ever read two ways, and a class, or an object that only fits, is refused with the fix. A policy is a prototype: every run, validation window and cost level deep-copies it before `init`, a search's trial, each of its pieces in a validation and each window of a validation's path running an instance of its own, built from the class with its parameters or copied from what a search's function returns, and the copy is `result.policy`, so two calls on one instance start alike and a chart draws the arrays the fills were decided on. `backtest` takes a second copy at the call, which its Result keeps until its baselines are first read and then plays once on the run's venue with the costs of trading removed; a run recorded below the full level, which has no baselines, keeps neither copy. emsl's cost sweep restored attributes by hand and missed what was mutated in place. The cost is a deep copy per run, which a policy holding a large model pays every time, and a second one each Result holds until its baselines are read.

**0025 A Strategy sees only the past and its own account.** A Strategy's `next(bar, account)` reads typed views of the current bar and of the account, and `bar.history` is its only window onto earlier bars, so logic computed inside `next` cannot read a later one. The account exposes the strategy's own orders, round trips and equity curve, so a strategy can size on its own record. `init` runs once over the whole series; `next` is not called before a declared warm-up, while the bars before it still advance and fill resting orders; parameters are the constructor's arguments; and at a validation seam, once every order the outgoing window left has been cancelled, `on_inherit(bar, account)` hands the incoming window the position it inherits before its first decision, the account's round trips and equity curve then counting from that close. emsl passed a state dict and the engine itself. The cost is Python on every bar for any logic that lives in `next`, and a hook for a strategy whose exits rest on the book to write, since a seam cancels them.

**0026 One Result and one Study.** Every run returns the same `Result`, whatever decided it: returns and equity as arrays, tables exposed through the Arrow C stream interface, so polars, pyarrow and DuckDB read them without probatum importing any of them, the totals of its costs, its graded assumptions, its baselines, and each instrument's position, weight and pnl under the instrument's name, a run recorded below the full level keeping its returns, equity and statistics, its ledger, its round trips, its costs and its assumptions, and no holdings, fill log, order log, baselines or record of an instrument's own. On disk a Result is a directory of open formats with a schema version, and its provenance records the data's fingerprint, the venue, the seeds and every package version the run loaded. A `Study` holds a search's trials or a validation's out-of-sample paths, its kind saying which. A search's is a table of its trials, a row each of its parameters, its state, its score and its statistics, beside every trial's returns, which the statistics across a search need and emsl discarded, and its winner as a Result run again when first read. A validation's is a table of its paths, each with its state, score, statistics and costs over the bars it owns, beside a table of its fits and one of each path's windows, which the statistics across folds read, and every path's returns; its winner, holdout and looks are those of the search it runs on the bars before the holdout. `combine` adds Results from different venues into one book on the times any of them has a row, refusing accounts kept in assets, or run on intervals or at rates, that do not add, and a run recorded below the full level. The cost is a returns matrix that grows with trials or paths and bars, which `keep="none"` drops with the statistics that read it.

**0027 Every assumption is graded.** Every run lists each modelling choice it made in one table: its value, its source, a grade, and what it cost in that run where its records measure it, so a run recorded below the full level, which keeps no fill log, prices neither the margin bound nor the liquidation, nor the fees after a liquidation. A choice is graded `venue` where the run does what a venue does as far as bars show it; `simplified` where it approximates that, with the direction it leans on the events it decides, pessimistic, optimistic or either; and `optimistic` where it leaves out a charge, a cost or a limit every venue imposes, or decides what a bar cannot show in the trader's favour, so a run with one is not a venue's whichever way it moved the numbers. A row describes the rule each instrument ran and takes the least favourable grade among them, a choice switched off is listed as off, never left out, and a result that ran with anything graded optimistic says so in its summary line. A fill or an order can be explained one at a time, and every Result recorded at the full level carries three baselines, computed when first read: holding cash, buying and holding, and the same policy on the run's venue with the costs of trading removed and every rule kept. Re-running a policy with each assumption moved was rejected: the table names every choice and prices those its ledger and fill log measure, and a choice they cannot price, intrabar first, is priced by running again with that one setting moved, which the user does. The cost is a table the user has to read, and a Result that keeps its data and its venue, and a copy of its policy until its baselines are read, which a run recorded below the full level spares by reading its assumptions as it ends.

**0028 Venue presets are dated data.** A preset is a TOML file with a published schema, dated and validated when it loads, so a new venue or a corrected fee table is a data change rather than a change to Rust. Each preset carries its own venue's rules, not one venue's copied to the others; a venue's spot and perpetual presets combine into one account rather than being written out twice; and the frictionless preset charges nothing and lifts the venue's limits, for teaching, while the baseline that separates an edge from what the venue took keeps the run's own venue and removes only what trading costs. The cost is that presets go stale as venues change their tables, and nothing checks them against the live venue.

**0029 One error tree.** Every error probatum raises derives from `ProbatumError` and from the built-in it means, so `except ValueError` still catches a bad value and a caller can also catch probatum's errors alone. A refusal is a kind where both its topic and its built-in are the kind's: `DataError` for bars, frames, features and a series an indicator reads, `VenueError` for a venue's settings and presets, `SpecError` for an agent whose spec does not match its run and `LookaheadError` for a policy the causality check finds deciding on bars that had not closed, each a `ValueError`, a policy whose runs on the same bars differ, which the check cannot compare, being a `ProbatumValueError`; `PolicyError` for a policy `backtest`, `search` or `validate` cannot run as given, a `TypeError`; and `MissingDependency`, an `ImportError` carrying the line that installs what is missing. Any other refusal is the root's class for its built-in, `ProbatumValueError`, `ProbatumTypeError`, `ProbatumKeyError` and so on, the four `ValueError` kinds deriving from the first and `PolicyError` from the second. A search or a validation that cannot go on, its workers lost, every trial or every path of it failed, or its winner run again not matching its trial, raises `ProbatumRuntimeError`, from which `ProbatumNotImplementedError` derives as `NotImplementedError` derives from `RuntimeError`. The built-in follows what arrived rather than how its check is written: a value of a type the argument does not take raises a `TypeError`, and one of its type that the call cannot take a `ValueError`, so a sizing of `5` is a `ProbatumTypeError` and one of `"weights"` a `ProbatumValueError`; a preset's file is the exception, every wrong setting in it a `VenueError` whatever its type, since the caller gave the preset's name and the fault is the file's. The binding raises the same classes. Each error names the argument, the value that arrived and the fix. Another library's error stays its own: the router's, the file system's, numpy's for values an indicator, `asof` or `features` cannot read as numbers, Python's `OverflowError` for an integer no float holds, and pyo3's for the binding's raw objects, whose arguments it converts, and for a panic; so does an error the caller's own code raises in a policy. Every warning is a `ProbatumWarning`, a `UserWarning`, and long work is logged to the `probatum` logger rather than printed. emsl raised the built-ins themselves. The cost is a class for each kind and each built-in to keep stable across releases, and catches narrower than they read: `except DataError` around a Data and `except VenueError` around a Venue built in Python miss an argument of the wrong type, and `except PolicyError` a policy's wrong values.

**0030 The statistics stay finite and rank monotonically.** The statistics use fixed conventions: the sample deviation for volatility and the Sharpe, the population deviation for Sortino's downside, and square-root annualisation. They stay finite on any run, so one degenerate run cannot poison a search: a zero denominator ranks at infinity for a positive reward and at zero otherwise, a losing run's Calmar is scaled by its drawdown rather than divided by it, drawdown is capped at a total loss, and a tail is taken by rank. Trade statistics are net of costs, and a metric that reads a run's bars checks it was given the same bars. A plain return series must state `periods_per_year`, which has no default anywhere, and takes its risk-free rate as an annual rate subtracted per bar, as a run does. A record keeps each statistic's own sign, a drawdown a positive magnitude, and its text prints a drawdown or a value at risk as the loss it is. The cost is conventions that differ from some other tools, written down so a reader can convert.

**0031 Every interval names its method.** The Sharpe's variance is the delta method over the joint moments of returns and squared returns: the long-run variance of the Sharpe's own influence series, with Newey and West's Bartlett weights at the lag their 1994 rule picks on that series, floored at its lag-zero value so autocorrelation can widen an interval and never narrow it. The interval, the probabilistic Sharpe and the minimum track record read that one variance and name its lag. It replaces emsl's effective sample at the first lag, which stays available by name. Each headline statistic has one interval, and its method is named: the delta method for the Sharpe; a stationary block bootstrap for statistics with a population value, its mean block the longest that Politis and White's rule, as Patton's code computes it, finds on the returns, their squared deviations or their tail, so a strategy's clustered exposure sets the blocks, and studentized on each statistic's own standard error for all but value at risk, since a percentile interval covers too little where the returns have heavy tails; a range of resampled histories for drawdown and Calmar, never called a confidence interval; and a bootstrap of round trips for trade statistics, studentized for the average trade and bias-corrected and accelerated for the profit factor, since a plain percentile interval covers too little on the skewed pnl of the few dozen round trips a backtest closes. A sample that cannot support an interval gets none: fewer than four returns, returns or round trips that never vary in what the statistic reads, an estimate ranked at infinity, a loss of everything for a statistic read on growth, or fewer returns, blocks or round trips than coverage needs. Two Sharpes on the same bars are compared by their difference, by the delta method and by Ledoit and Wolf's studentized circular block bootstrap, both reported; alpha and beta are estimated against buying and holding unless another benchmark is given; and the order of trades is permuted with each trip's return on the equity it opened on. Every interval is held by simulation to cover between 93% and 97% of the time at 95% on the shapes and sizes its coverage cells draw, and returns in stretches too long for their length are held to the floor that refuses them. The cost is that intervals are computed when first read, never inside a search, so a search ranks on point estimates, that a short run, or one whose exposure switches in stretches too long for its length, has no interval of its returns but the Sharpe's, and that the block lengths and the Sharpe difference's kernel follow Politis and White and Newey and West rather than each paper's own calibration.

**0032 A search never sees its holdout.** `search` scores every trial on one run over the bars before the holdout, which is always the tail; `evaluate_holdout` runs the winner there once and counts the look as soon as the winner is handed those bars, so a run that raises there has spent it. A validation holds out the same tail and chooses what runs there by a search over the bars before it, run first, whose looks it counts. Every trial counts in the deflation, failed and floored ones included: `min_trades` floors a trial with too few round trips, which has no score and is told to TPE as failed but keeps its statistics and its returns, so a floor that binds over much of the space still leaves its trials in the record. The deflated Sharpe takes a random-search null over the same space and bars, because a TPE search concentrates its trials and cannot supply its own spread. The random and grid samplers are probatum's own, drawn from named streams, a log scale's logarithm and exponential taken through `libm`, so a seeded search repeats on every machine; TPE is Optuna's, every argument Optuna 5.0 keeps set explicitly and the eight it deprecates left at the recorded version's defaults, so a seeded TPE search repeats on the machine it ran on. Workers start with `spawn` and rebuild the engine from files rather than receive one, a policy's decisions are checked for causality by cutting the bars, on the first trial that decided anything and on the winner, and in a validation on its first search's, on each other winner its fits chose and on each path that ran, at its seams, where `on_inherit` decides, and a random or grid search over arrays runs its trials in Rust, each on an engine of its own over the shared bars, in parallel with the GIL released, where TPE, which chooses each trial from those told before it, runs them one at a time in this process or a round of `n_jobs` at a time in the workers. The cost is a holdout that can be spent once, with every further look counted.

**0033 A search is judged across all its trials.** A search reports the deflated Sharpe against every trial and against the effective number of trials, the probability of backtest overfitting, White's Reality Check and Hansen's SPA against a stated benchmark, and the minimum backtest length. The deflated Sharpe is the winner's probabilistic Sharpe, on the variance ADR 0031 fixes, against the Sharpe the best of that many trials reaches by luck, Bailey and Lopez de Prado's expected maximum of independent normal draws: it counts every trial the search asked as a look, and takes the spread of Sharpes from a random search over the same space and bars, every trial of it that ran, so neither a sampler's convergence nor an activity floor narrows it. At the effective number of trials the search's own trials are clustered as Lopez de Prado and Lewis cluster them, by k-means on the distances of their correlations, keeping the clustering whose silhouettes are most consistent, each cluster's returns combined at minimum variance, and the threshold reads the number of clusters and the spread of their Sharpes; the Sharpe deflated there is that of the winner's cluster, as Lopez de Prado's own example deflates each cluster's series, since the winner's own beside a threshold of clusters leaves out the choice made inside its cluster, and rejects far more often than one search in twenty that has no skill. The overfitting probability is computed by combinatorially symmetric cross-validation on the returns each trial earned in its own run, never by re-simulating recombined blocks, which emsl rightly refused for a path-dependent engine, so it ranks only on statistics that do not depend on order: sixteen blocks, every one of the 12,870 halvings, the winner of one half ranked on the other, and overfit where that rank falls below the median. The Reality Check and SPA test the trials' log growth over the benchmark by one stationary bootstrap that every trial shares, its mean block the median of Politis and White's lengths on the trials, and SPA studentizes each resample on its own stationary-bootstrap variance, since a variance fixed at the sample's leaves the test oversized where the block is long beside the sample. The minimum backtest length is the years over which the expected best of that many trials would fall to the winner's Sharpe. The plateau reads the trials around the winner: each numeric parameter put on [0, 1] across its range on the scale it was drawn on, a categorical one 0 apart where its choice is the winner's and 1 where it is not, the Euclidean distance over them, and at each radius from 0.05 to 0.5 the share of the other configurations within it, each counted once, that completed past a stated level, so a winner alone on a spike reads as one. The deflated Sharpe, the overfitting probability, the Reality Check and SPA are tests on random or grid searches, labelled descriptive on an adaptive one. The cost is that every trial's returns must be kept; that the deflated Sharpe rejects at 0.95 about one search in twenty that has no skill at two trials, where the threshold falls short of the best of two by luck, and fewer the more trials it counts; that the effective number rests on a clustering whose quality can be nearly flat across counts and whose time and memory grow with the square of the trials, and judges the winner's cluster rather than the winner; that the Reality Check and SPA reject more often than their level where the growth is autocorrelated, White's the more, since the stationary bootstrap's variance there is short at the block its rule chooses and noisy at a longer one; that SPA studentized in each resample departs from Hansen's published test and costs a Fourier transform of every trial in every resample; and that the plateau weighs every parameter alike across its own range and holds less of the space the more parameters it has, so a search over many reads as spikier.

**0034 A validation path is one run.** A path is one engine pass over the bars before the holdout with a composite policy that hands each window the closes of its test span, so the account carries across seams and every window's warm-up sees the bars before it in `init` and `bar.history`; stitching separate runs would reset the account and invent trades at every seam. A window owns what its decisions govern, the bars from the one after its first decision to the one after its last, and each window and each path is scored on its own bars of the run that happened. Seams are explicit: at the incoming window's first close every order not yet filled is cancelled with the reason `seam`, the targets are forgotten and `on_inherit` hands the position over; with `seam="flatten"` the outgoing window's last close closes every position instead of deciding, its fills marked `seam`, where emsl left resting orders behind with nothing owning them. Every fit of a function decides in the kind its first search's winner decided in, weights or a Strategy, so a path is one kind of run. A function's weights and a model's trade as an array, each window's from its fit, with the barriers the function returned or the model's labels were made with; an array has no `on_inherit`, so at its seam the inherited round trip's bracket is placed again at its entry, the legs still resting alone, or after a flattening close those resting until it, and its latch is kept, the trade keeping the exits it opened with. A model reads its features, computed once on the whole Data and refused before any fit where cutting away the bars after a row changes them, as its final fit's predictions and weights are refused where cutting away the rows after one changes them, and fits each split's training rows that are available, finite, labelled and left by the purge, in time-major order, with its labels' uniqueness as sample weights where `fit` takes them; every fit starts from a fresh estimator, scikit-learn's `clone` of the one given or a call of the function given in its place, so no fit sees another's rows. Its skill is read apart from `to_weights` and the costs: Spearman's correlation of its out-of-sample predictions with the returns of its labels that end before the holdout over each path's rows and over every path's, its standard error Newey-West over the bars at a lag of the longest label, and the R squared against a forecast of zero. The cost is windows that cannot run in parallel; a position a Strategy's window inherits with nothing resting until its `on_inherit` places it; a model fitted only on the rows its features and labels read, fewer than the bars; and a correlation pooled over bars and instruments, which credits a forecast of when the market moves as well as of which instrument moves most.

**0035 Splitters purge by label end.** The splitters divide bars, into groups as scikit-learn's KFold divides samples, so `CombinatorialPurged(k, 1)` is `PurgedKFold(k)`, and work on the rows in the time-major form an estimator sees, each row's label end an int64 bar given at construction as `(T, N)`, so a row's bar is known, and the least int64 where a row has no label. A training row is purged where its label reaches a test span or where it starts before the latest end of a label that tests in one, so a label censored or running into a holdout, which tests nothing, reaches nothing, a span being a run of adjacent test groups, and the embargo removes the bars after that end; the intervals are closed, as the book's 7.4.1 states them, which removes a bar more on each side than its snippet 7.3, and a label that ends past the last bar divided, censored or running into a holdout, never trains. An embargo left as None is the longest label held, and `validate` passes a model's `labels.end` to a splitter built without `end`. CombinatorialPurged's path `p` takes each group from the `p`-th split that tests it. WalkForward places its windows from the first bar, so appended bars move only its last, and it and Holdout take no embargo, since no training row follows their test spans. scikit-learn's TimeSeriesSplit cuts rows with a fixed gap and purges no label. The splitters meet scikit-learn's contract without importing it, refuse a split the purge leaves empty rather than skip it, and carry no `shuffle` or `random_state`, which scikit-learn's own code reads and writes; `validate` takes only these, since it purges their spans and recombines their paths. A Strategy has no labels: its test span reaches the bar its last decision is scored on, and each contiguous piece of a training span is its own run, a piece after a span on a Data of its own that starts after that bar and opening only past the embargo and its warm-up, so its embargo is at least its warm-up, and past the fill window of each instrument that printed before it, or its last bar there, a window counted with the bar its first return is measured from at every fill model, so the pieces do not move when the costs change. The cost is a splitter built once per series, since one built for a series refuses a fold's rows, one fit's trials scored on bars that differ a little after each span, fewer for a longer warm-up, and a bar more than a venue without impact needs.

**0036 Labels are trades through the same fill model.** A label is what a trade of a stated notional, entered at the next open, would have returned through the same fill model as a backtest, net of fees, funding, spread, slippage and impact, with optional barriers. A short label is computed on its own rather than as the long one's negative, since both pay costs and funding changes sign. A label whose horizon runs past the data is censored even when a barrier was hit first, so censoring never depends on the outcome, and every label carries its end, the bar whose price closed its trade, from the bar after its own on, past the last bar where it is censored and the least int64 where there is no label, as the splitters read it, and its average uniqueness. Each label is a fresh account on its instrument holding the notional alone, so it pays what one trade of that size pays and closes as such a trade would, at its stop, its take-profit, its horizon, its close placed again at each close while some is left, a delisting or a liquidation, its bracket placed at the close of the bar its entry filled on as an array run places one; its average uniqueness counts the labels of its instrument that have a return, over the bars from its entry's fill to its end (Lopez de Prado 2018, chapter 4), since the instruments' trades draw on different prices. The cost is that labels run the engine, slower than returns read off the closes.

**0037 Indicators run over each instrument's own bars.** `probatum.ta` keeps emsl's closed set of indicators and states each one's convention where implementations differ. Every function returns one value per bar with the warm-up as NaN, never a shorter array; crossings return booleans that are false during the warm-up; and a shift pads rather than wraps. A function takes a series `(T,)` or a universe `(T, N)`, time along `axis`, the first by default, and returns the shape it was given, computing each column over its own values: a value that is NaN or infinite is a row the column does not have, so a window, a smoother, a lookback and a crossing carry across it, and the output there is NaN, or false for a crossing. For a Data's bars that is exactly where an instrument printed nothing, so a closure neither breaks an indicator nor restarts it, while `funding_rate` and what `asof` puts on the clock hold their last value through one. A function built from others hands each its own output, whose NaN are skipped in turn, and a series too short for its warm-up is all warm-up, only one of no bars being refused, so every prefix of a series that has a bar gives the first rows of the whole, and each column is the function of that column alone, to the bit. emsl restarted every indicator after a gap, lagged by rows, refused a two-dimensional array and a length longer than the series, and flattened a `(T, 1)` column. The recursive smoothers are vectorized, which keeps them within rounding of a per-bar loop rather than bit-identical to it. The costs are that an indicator outside the set is the user's to write, and that a read by row offset in `next` can land on a row an instrument did not print, where `shift` reads its own last bar.

**0038 The environment shows the agent its account.** `probatum.env` is a Gymnasium vector environment over the Rust batch, with all three of Gymnasium's autoreset modes and `NEXT_STEP`, Gymnasium's own default, as its default, where emsl had `SAME_STEP` alone; the Stable-Baselines3 adapter switches to `SAME_STEP`, which SB3 expects. Every observation carries the account (weights, unrealized PnL and margin), so an agent sees what it holds, and actions are normalised by gross exposure, so an untrained policy over many instruments cannot ask for many times its leverage. Order actions are decoded in Rust, which ends emsl's market-order-only batch, the reward is floored so a liquidation is a large finite penalty, and costs can be drawn per environment. The cost is an observation larger than the market data alone.

**0039 An agent carries the spec it trained with.** An agent is judged fairly only if it sees in a backtest what it saw in training, so `probatum.env` records its keywords as a versioned JSON spec, with any normalisation statistics, the training span's fingerprint and the venue, and `backtest` rebuilds the observation from it. A custom function is never pickled: the spec records its name, its width, a hash of its source and its output on a dataset shipped with the package, and a function passed again that gives a different output is refused. The cost is that a custom feature function has to be passed again at every backtest.

**0040 One output buffer, and a path to the GPU.** The batch fills one writable float32 buffer in place, and every framework reaches it by its own zero-copy path, so none is special inside the engine; observations are handed out as copies by default, so a replay buffer stays safe. `TensorEnv` moves them to a device through pinned double buffers, and its resident mode copies the features to the device once and gathers each window there, so only offsets and account values cross the link each step. A single environment fills the same buffer, which replaces emsl's read-only view onto the candle buffer, since an observation now carries the account as well as the bars. Engines and environments clone, so a fork for planning repeats its original exactly. The cost is a second code path for the device, held bit for bit to the host's.

**0041 Reports are static figures over the Result.** Reports and figures are matplotlib figures with a pinned font, embedded as SVG in one HTML file with no JavaScript. They plot fields of the Result and compute nothing, so they can be redesigned without moving a number, and they are checked by the data they plot rather than by their pixels. The cost is plainer pictures than an interactive dashboard would give.

**0042 The interactive chart is kept as emsl built it.** The candle chart stays as emsl built it, for inspecting trades, and stops growing. It is precomputed in Python and self-contained in one HTML document with its renderer vendored, so a saved chart works offline; it draws arrays that arrive computed and knows no indicator names; Python and JavaScript meet at one spec, with the JavaScript computing geometry and never policy; plotting is never declared inside a strategy; and a series is aligned by position, a NaN breaks the line, and a bare array overlays the candles unless it would flatten them. The renderer's attribution is shown, as its licence asks. The cost is that new work on pictures goes to the static figures instead.

**0043 The maths is verified inside the repository.** There is no reviewer and no check against a live venue, so the maths is proven in the repository: every rule is written in the Specification with an equation and a worked example before it is coded, and every worked example is a test. A reference simulator, written from the Specification and never from the engine, finds the liquidation path's crossings by bisection where the engine solves them in closed form, and the two are compared on every ledger column over random cases, with tolerances derived from the magnitudes involved. Tests are named as the claims they prove and run over a deliberately awkward fake market at every depth, and every code block in the documentation is executed. The cost is a second simulator maintained beside the engine.

**0044 The core depends on numpy alone.** Everything else is imported when used, so a backtest never loads Gymnasium; three extras cover probatum's own optional features, and frameworks the user brings, such as torch, are never extras, because an extra would install a build over the one the user chose. Python versions follow Scientific Python's SPEC 0, dependencies carry no upper bounds, and wheels ship for Linux, macOS on Apple silicon and Windows, with no free-threaded build in 2.0.0. The package declares `MIT AND Apache-2.0`, because the wheel ships the chart's renderer. The cost is that an older Python or an Intel Mac is not supported.

**0045 A strategy is judged at the size and the costs it would trade.** `capacity` runs a policy again at each of several balances, and `cost_curve` at each of several multiples of every cost its venue charges for trading together, its fees, its spread, fixed or estimated, its slippage and its impact coefficient, since a sweep of the fee alone, as emsl's was, leaves out most of what a venue charges once its spread and impact are priced. Each level runs a fresh copy of the policy, as a backtest does, and records what moves with it: the return, the Sharpe, the turnover a year and the round-trip cost the run paid, in basis points of the notional its fills traded, with the impact paid and the share of orders the liquidity budget held at each balance, and each cost paid at each multiple. `breakeven_bps` bisects the multiple at which the return reaches zero and gives the round-trip cost paid there, so a strategy reads as dying at so many basis points a round trip beside what its venue charges. A rebate, a fee rate below zero, is the venue's payment and is not moved, nor are the liquidity budget, funding and a liquidation fee the venue sets, being the market's limit and rates rather than charges for trading; one it does not set is the taker rate, and moves as it does. The cost is that a multiple of a venue's costs is not a venue anyone quotes: impact grows with a fill's size, the costs change which fills happen and how large, and a fill's slip stays held below the price, so the round-trip cost is measured from each run rather than set, and the bisection finds a crossing rather than the crossing.

**0046 A Study is kept on disk, and a search resumes from it.** `study.save(path)` writes a Study as a directory of open files, as a Result is written (ADR 0026): a manifest holding the format, the version that wrote it, the provenance, the looks, the winner and a search's space; each table as an Arrow IPC file, a search's trials beside each trial's choice of a categorical parameter as its index, since the table prints some choices alike, or a validation's paths, fits and windows; the returns as a NumPy array; and the winner's in-sample Result, and its holdout's once run, as Result directories. `Study.load(path)` reads it back with every table and statistic, and a loaded Study, which holds no policy and no data, refuses only what would run the winner again. `search(..., storage=path)` keeps its Study there as it runs, each batch of trials written as it arrives and the whole Study when it ends, and the same call made again resumes it through the search's own loop: each stored trial is taken in its turn rather than run, once the sampler asked for it again gives the stored parameters, so the random stream and TPE's history stand where they stood and the causality check falls on the trial it fell on; the first stored trial that ran is run again and must give its stored statistics; and only the trials not stored run, so the Study is the one a search that never stopped returns. A directory holding another search is refused, naming the setting that differs, and a larger `trials` extends a random or TPE search that ended. A look is counted before the winner is handed the held-out bars, in every directory the Study was saved or kept in that still holds its search, as one more than the most counted there, a manifest set aside as a save puts the new one in place, so neither a reload, a resume, a save stopped part way nor a second Study of the same search kept there loses one; a resume that changes the winner, or finds the held-out bars revised, keeps the looks and drops the holdout it held. A trial that failed because the workers broke is not stored, nor is the Study of a search whose workers broke, and a Study saved with such trials names them, so a resume runs them; and save refuses a directory where it could delete another's files: one holding files but no Study, or a manifest it did not write. The cost is a directory that grows with each batch until the search ends, a TPE search that resumes only at the number of workers and on the machine it ran on, as it repeats only there (ADR 0032), a policy's code, which no file holds, checked by one trial run again, and a resume's final save that stops part way, after which the trials of the Study it resumed run again.
