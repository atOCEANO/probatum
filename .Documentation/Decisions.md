## Decisions

The record restarts at 0001 with probatum. emsl's record is absorbed rather than continued: every decision it took that still holds lives inside one of these.

Each entry is one paragraph. It says what was decided and what the decision costs; the rules themselves are stated in full in the [Specification](Specification.md).

<br>

**0001 probatum replaces emsl rather than staying compatible with it.** probatum is emsl's repository renamed and released as 2.0.0. Where emsl simulated something a venue does not do, probatum's result changes rather than repeating it. A compatibility mode that kept emsl's numbers was rejected: it would be a second engine to test, and a way to reach a flattering number by accident. From 2.0.0 the simulator's behaviour is part of the API, so a public name, a keyword's meaning, a return type or a rule this record sets changes only in a major release, with a record saying what was wrong. The cost is that emsl and probatum can give different results on the same bars.

**0002 Four depths of one step.** Data, run at a venue by a policy, gives a Result. An array of weights, a Strategy, the caller's own loop around the Engine and a trained agent are four depths of one step, and all four record the same Result, so moving from one to another never changes what a number means. The environment an agent trains on steps the same accounts. The venue is an argument of every verb, and no verb takes a single venue setting as a keyword, so a setting has one place to be given. The cost is that changing one fee for one run means building a variant of the venue with `replace`.

**0003 Every run steps every bar.** Stops, limits, funding and liquidation depend on the path a position took, so every run steps every bar through one event loop, and a decision made at a bar's close fills at the next bar's open. A vectorized backtest was rejected because it simulates an easier market than the real one. Speed comes from where the loop runs: an array run is stepped whole in Rust, a Strategy calls Python once per bar, and the batch steps thousands of accounts with the GIL released. The batch steps the same engines the Python verbs drive, so nothing has to be compiled first. The cost is that a search over thousands of parameter sets pays for thousands of full runs, which the batch makes fast but never free.

**0004 Time is the bars that exist.** Every bar carries its open time in UTC nanoseconds, and a Data's clock is the set of times at which any of its instruments printed a bar, with nothing invented between them. A market that closes on Friday opens its next bar on Monday: positions carry across the gap, indicators run straight across it, and an order decided at Friday's close fills at Monday's open. Annualisation counts the clock's own rows per year rather than assuming a number. The cost is that bars without times cannot run, so a Data built from arrays needs `time=`.

**0005 A Data owns its bars.** A Data copies its input once and every view of it is read-only, so no later edit can change the bars under an unchanged fingerprint. That fingerprint, 128 bits over everything a run reads, travels into every result. A Data holds a universe: instruments keyed by venue, market and symbol, each entering at its first bar and leaving at a delisting time where its venue's table gives one. It saves to a directory the user names, as Arrow files, and probatum keeps no store of its own. The cost is one full copy of the bars per Data, and a universe that is only the user's own list of symbols.

**0006 Coarser bars and outside series arrive when they were known.** A decision at a bar's close may use only what was known by that bar's end, and data on another clock is where bar research most often breaks that. `resample` builds coarser bars from whole multiples of the interval and drops a coarse bar the data does not cover to its end. `asof` puts each value from another clock on the row by whose end it was known, never on the row whose open time matches it. Together they give decisions on a coarse clock with execution on finer bars, without a second clock in the engine. The cost is that an outside series joined some other way is invisible to probatum, so it cannot be refused.

**0007 The boundary refuses what it cannot simulate.** Every argument is checked where it enters, and a value the engine cannot simulate is refused, never repaired: a non-finite setting, a price at or below zero, a bar whose high and low do not contain its open and close, a negative volume, an order that can never fill. The refusal names the argument, the value that arrived and the fix. Every path into a venue setting passes one validator, so no path admits a value another refuses. The cost is that a feed with one bad bar has to be cleaned before it runs.

**0008 One account, two wallets.** An account keeps the two wallets venues keep. The spot wallet holds cash and spot holdings, never borrows, cannot short and is never liquidated. The margin wallet backs every perpetual in cross margin, so one balance carries them all and a liquidation closes them all together. Cash moves between the wallets only by a transfer, decided at a close and applied at the next bar. Isolated and unified margin were left out, each a different liquidation rule. The cost is that a carry trade moves its own collateral, as it would on the venue.

**0009 A size's unit is its verb.** `buy` and `sell` take base units, or contracts on an inverse instrument, `buy_value` and `sell_value` take the quote currency, and `target` takes signed weights of equity, so a size is never read in a unit its caller did not mean. `target` turns weights into legs at the close and places every reducing leg before every growing one, so a rebalance is funded by its own sales. An array run gives every position the barriers `labels` uses, so a model trades the way its labels were made. The cost is three verbs where a keyword could have chosen the unit, and an array whose weight never changes that does not enter again after its first barrier.

**0010 Orders keep emsl's semantics, on a named instrument.** Every order type emsl had stays, now on a named instrument, with the rules it settled: time in force, all-or-nothing judged after every clamp, a stop that cannot fill has not triggered, and `replace` keeps an order's id. `reduce_only` now works on every order type, a `post_only` limit the first bar opens through is cancelled, and `bracket` places two exits as one OCO pair. Every verb that places an order returns its `Order` handle, refused ones included with their reason. The cost is a handle object per order.

**0011 A resting limit is on the book.** A limit is a taker only on the first bar after its placement, when that bar opens at or through it; once it has rested through a bar it fills as a maker. A limit that would trade against the account's own resting limit is refused, as venues refuse it. Resting orders on every instrument share one slot table and resolve in slot order, so when a clamp binds, which order gets the room is fixed. The cost is that a strategy built on crossing its own orders sees them refused.

**0012 What a bar cannot show is decided by one setting.** A bar gives four prices and not the order between them, so some outcomes cannot be read from it: a stop and a take-profit both reached, a take-profit and the liquidation trigger both reached, how much of a bar came after a fill inside it, several instruments each at their worst. One venue setting, `intrabar`, decides all of them alike. Pessimistic is the default everywhere: the worse of two exits fills first, a take-profit on a liquidating bar is held back, and every instrument reaches its worst price at once. Optimistic decides each event the other way, and random draws each from a seeded stream, for training only, so an agent cannot learn a fixed tie-break. The cost is a result that depends on a setting the user may not know is there, so every result says which way it ran.

**0013 A fill is what a venue would give.** A taker fills at its reference, the next open or a stop's trigger where that is worse, moved against it by half the spread, the slippage and the impact, and held inside the bar's range, so no fill prices where the bar never traded. Each part of the fill model is a choice in the venue rather than a constant: how limits fill, the trailing window, a liquidity budget per bar, the spread, square-root impact, the fees, and the lot, tick and minimum notional. Presets take the realistic option in every row, and a hand-built venue starts from the plain one. The cost is that a preset's slippage and impact are a starting calibration, not a measurement of anyone's costs.

**0014 A flip realizes through zero, and each fee is paid once.** A fill that crosses zero closes the old side at its average entry and opens the rest at the fill price, and an add on the same side volume-weights the entry. A round trip carries its entry fee and its exit fee exactly once, so on a run that ends flat with no liquidation charge or dust adjustment, the round trips' net PnL equals the change in equity. Money is float64, updated in event order with plain arithmetic, so any amount can be followed by hand. The cost is that a position below the dust threshold is swept and booked as a dust adjustment rather than held.

**0015 Margin is shared, and an account over its cap may only shrink.** In cross margin the sum of each perpetual's notional over its tier's maximum leverage may not exceed margin equity. A growing fill is clamped to what the cap allows, and the clamp is logged. An account over the cap because equity fell is never force-reduced, only kept from growing, and one at or below zero equity may only shrink. Maintenance follows the venues' tier tables, by notional or by contracts. The cost is tier tables that are dated data, kept current by hand.

**0016 Inverse contracts are linear in the reciprocal of the price.** An inverse perpetual is quoted in dollars and settled in its coin. Every quantity the account counts on it, its profit, notional, fees, funding and requirement, is linear in `1 / p`, so the engine runs an inverse account as a linear one in the reciprocal of the price and reuses every closed form. A taker's spread, slippage and impact move `1 / p` too, so each costs its rate of the coin notional. An account has one settlement asset, so an inverse account holds that one perpetual, and its results are in the coin, with equity valued in dollars beside them. The cost is that a book of several coin-margined contracts runs as one account per coin.

**0017 A liquidation is a price on the bar's path.** A bar whose prices reach the trigger liquidates the account on that bar. The bar's own trade prices decide, rather than a mark price, which exchange-router does not serve as history, and they err toward liquidating. Every perpetual held moves along one adverse path, from its last mark to its open and from its open to its adverse extreme. Equity is linear along it and the requirement piecewise linear, so the first crossing is solved exactly rather than searched for, and no order fills past it. The cost is that a position within a wick of its trigger is liquidated where a venue marking on a smoother price might have kept it.

**0018 No account ends a bar owing money.** A takeover leaves the margin wallet at exactly zero, and whatever it still held, positive or negative, is booked as the liquidation charge. Every reducing fill passes a margin bound as it lands, so no order of fills inside a bar can realize past the point where the margin runs out. A fill the bound lifts stays inside its bar, and the part the bar cannot hold is booked as a negative charge. A liquidation cancels every resting perpetual order. The cost is a negative liquidation charge, a number with no line on a venue's statement, standing in for the insurance fund.

**0019 Each venue liquidates in its own way.** The forced close is a choice in the venue. Takeover, which Binance, Bybit and OKX use and every hand-built venue starts from, closes every leg where the path crosses the trigger and books what remains as the liquidation charge. Book then backstop, Hyperliquid's, sells every leg into the book from its trigger as a taker and leaves the trader what remains. It falls back to the takeover where the sale would leave the trader below the backstop level, or where the bar reaches that level too (0012). One generic rule was rejected because the two leave a trader very different amounts. The cost is a second liquidation model to keep tested against the reference.

**0020 Funding is charged when the venue charges it.** Funding events are read at their real times from the venue's history, with each symbol's interval as it changed. A bar owns the events stamped after its open and up to its end, and charges them at its close after the liquidation check, so an account liquidated before a stamp pays nothing for it. An event stamped between bars, across a closure or a hole in the data, is charged at the next bar's start, so no decision sees a rate published after it. The cost is funding priced at the close rather than at the venue's mark.

**0021 The same numbers on every machine.** A run gives the same bits on every supported platform. Every transcendental function goes through `libm`, integer powers are written as products, sums run in a fixed instrument order, and every random draw comes from a named stream derived from the run's seed. A statistic's resampling is seeded by a digest of the values it resamples, so an interval is the same on every read and in every process. Reported totals are compensated sums, while cash and positions stay plain arithmetic in event order. The cost is that the engine cannot use the platform's faster maths, nor reorder a sum for speed.

**0022 A run records its ledger, its fills and its orders.** A run records a ledger row per bar, its holdings per bar and instrument, a fill log with each fill's reference price and every cost measured against it, and an order log with every order's events and the reason for each, so the log says why a fill came out smaller than its order. A value the record does not have is missing, never a number that stands for none. The ledger identity, the change in equity equal to price PnL less every cost, holds within an error bound, and each term is computed on its own, so none is a residual that passes by construction. Recording levels trade detail for memory: `full` keeps all of it, `account` keeps the ledger and the round trips, and `transitions` adds each step an agent took (0040). The cost is memory: a full ledger of a large universe runs to hundreds of megabytes.

**0023 A trade is a round trip.** A trade opens when a position leaves zero and ends when it returns to zero or flips, and resizing inside it does not end it, so `num_trades` counts decisions rather than fills. Its net PnL is after its fees and the funding it paid while open. A round trip still open at the end is reported, marked at the last close and flagged. Its best and worst excursions are bounds over the part of each bar it was in, so neither overstates. The cost is that a strategy that scales in and out reads as one long trade.

**0024 `backtest` accepts anything that decides, read one way.** `backtest` dispatches in one fixed order, a table, an array, a Strategy, a Stable-Baselines3 model, a torch module and then any other callable, so no input is ever read two ways, and anything else is refused with the fix. A policy is a prototype: every run deep-copies it before `init`, and the copy is `result.policy`, so two calls on one instance start alike and a chart draws the arrays the fills were decided on. A second copy, kept until the Result's baselines are first read, runs once more without the costs of trading. The cost is a deep copy per run, which a policy holding a large model pays every time.

**0025 A Strategy sees only the past and its own account.** A Strategy's `next(bar, account)` reads views of the current bar and of the account, and `bar.history` is its only window onto earlier bars, so logic inside `next` cannot read a later one. The account exposes the strategy's own orders, round trips and equity curve, so it can size on its own record. `init` runs once over the whole series, `next` starts after a declared warm-up, and parameters are the constructor's arguments. At a validation seam, `on_inherit(bar, account)` hands the next window the position it inherits. The cost is Python on every bar for any logic in `next`, and a hook to write for a strategy whose exits rest on the book, since a seam cancels them.

**0026 One Result and one Study.** Every run returns the same `Result`, whatever decided it: its returns and equity as arrays, its tables through the Arrow C stream interface, so polars, pyarrow and DuckDB read them without probatum importing any of them, the totals of its costs, its graded assumptions, its baselines and each instrument's record. On disk a Result is a directory of open formats, and its provenance records the data's fingerprint, the venue, the seeds and every package version the run loaded. A `Study` holds a search's trials or a validation's paths, with every trial's returns, which the statistics across a search need, and its winner as a Result. `combine` adds Results from different venues into one book. The cost is a returns matrix that grows with trials and bars, which `keep="none"` drops with the statistics that read it.

**0027 Every assumption is graded.** Every run lists each modelling choice it made in one table: its value, its source, a grade and, where its records measure it, what it cost in that run. A choice is graded `venue` where the run does what a venue does as far as bars show it, `simplified` where it approximates that, with the direction it leans, and `optimistic` where it leaves out a charge or a limit every venue imposes, or decides what a bar cannot show in the trader's favour. A choice switched off is listed as off, never left out, and a result that ran with anything optimistic says so in its summary. Every Result recorded in full also carries three baselines: holding cash, buying and holding, and the same policy with the costs of trading removed. Re-running a policy with each assumption moved was rejected; the table names every choice, and moving one is a run of the user's. The cost is a table the user has to read, and a Result that keeps its data, its venue and a copy of its policy until its baselines are read.

**0028 Venue presets are dated data.** A preset is a TOML file with a published schema, dated and validated when it loads, so a new venue or a corrected fee table is a data change rather than a change to Rust. Each preset carries its own venue's rules, and a venue's spot and perpetual presets combine into one account rather than being written out twice. The frictionless preset charges nothing, for teaching, while the baseline that separates an edge from what the venue took keeps the run's own venue and removes only the costs of trading. The cost is that presets go stale as venues change their tables, and nothing checks them against the live venue.

**0029 One error tree.** Every error probatum raises derives from `ProbatumError` and from the built-in it means, so `except ValueError` still catches a bad value and a caller can also catch probatum's errors alone. A refusal of a known kind has its own class: `DataError` for bars, frames and features, `VenueError` for a venue's settings and presets, `SpecError` for an agent whose spec does not match its run, `LookaheadError` for a policy that decides on bars that had not closed, `PolicyError` for a policy that cannot run as given, and `MissingDependency` for a missing optional package, carrying the line that installs it. Any other refusal is the root's class for its built-in, such as `ProbatumValueError`, and a search that cannot go on raises `ProbatumRuntimeError`. A value of the wrong type raises a `TypeError`, and one of the right type that the call cannot take a `ValueError`. Every warning is a `ProbatumWarning`. The cost is a class for each kind and each built-in to keep stable across releases, and catches narrower than they read: `except DataError` misses an argument of the wrong type.

**0030 The statistics stay finite and rank monotonically.** The statistics use fixed conventions, the sample deviation for volatility and the Sharpe, the population deviation for Sortino's downside and square-root annualisation, and they stay finite on any run, so one degenerate run cannot poison a search. A run's record, which describes the run where a search ranks it, holds none where the number would describe nothing, each with its reason: a CAGR off a run shorter than a year, the ratios of returns that never vary, and the round trips' rates where none closed. A plain return series must state `periods_per_year`, which has no default anywhere. The cost is conventions that differ from some other tools, written down so a reader can convert, and a search that ranks a trial on a number its record does not show.

**0031 Every interval names its method.** Each headline statistic has one interval, and its method is named. The Sharpe's comes from the delta method over the long-run variance of its influence series, with Newey and West's weights at their 1994 lag, floored so autocorrelation can widen an interval and never narrow it. Statistics with a population value use a stationary block bootstrap whose blocks Politis and White's rule sets on the returns, studentized for all but value at risk; drawdown and Calmar get a range of resampled histories, never called a confidence interval; and trade statistics get a bootstrap of round trips. A sample too small for an interval gets none. Every interval is held by simulation to cover between 93% and 97% of the time at 95%. The cost is that intervals are computed when first read, never inside a search, so a search ranks on point estimates, and that a short run has no interval of its returns but the Sharpe's.

**0032 A search never sees its holdout.** `search` scores every trial over the bars before the holdout, which is always the tail, and runs the winner there once, counting the look as soon as the winner is handed those bars. A validation holds out the same tail. Every trial counts in the deflation, failed and floored ones included, and the deflated Sharpe takes its spread from a random search over the same space and bars, since a TPE search concentrates its trials and cannot supply its own. The random and grid samplers are probatum's own, so a seeded search repeats on every machine; TPE is Optuna's and repeats on the machine it ran on. A policy is checked for decisions on bars that had not closed, on the first trial that decided anything and on the winner. The cost is a holdout that can be spent once, with every further look counted.

**0033 A search is judged across all its trials.** A search reports the deflated Sharpe, against every trial and against the effective number of trials, the probability of backtest overfitting, White's Reality Check and Hansen's SPA against a stated benchmark, the minimum backtest length and the plateau around its winner. The deflated Sharpe counts every trial the search asked as a look. The overfitting probability comes from combinatorially symmetric cross-validation on the returns each trial earned in its own run, never from re-simulating recombined blocks, which a path-dependent engine cannot do. These are tests on random or grid searches, and are labelled descriptive on an adaptive one. The cost is that every trial's returns must be kept, that the clustering behind the effective number grows with the square of the trials, and that the Reality Check and SPA reject more often than their level where the growth is autocorrelated.

**0034 A validation path is one run.** A path is one engine pass over the bars before the holdout, with a composite policy that hands each window the closes of its test span, so the account carries across seams and every window's warm-up sees the bars before it. Stitching separate runs would reset the account and invent trades at every seam. Seams are explicit: at a window's first close every unfilled order is cancelled with the reason `seam` and `on_inherit` hands the position over, or with `seam="flatten"` every position is closed instead. A model's features are refused before any fit where cutting the bars after a row changes them, every fit starts from a fresh estimator, and its skill is read apart from the costs, as a rank correlation with its labels. The cost is windows that cannot run in parallel.

**0035 Splitters purge by label end.** The splitters divide bars into groups as scikit-learn's KFold divides samples, and work on the rows an estimator sees, each with its label's end. A training row is purged where its label reaches a test span, and the embargo removes the bars after that end. WalkForward trains each window on the bars before it, and CombinatorialPurged recombines its splits into several paths. The splitters meet scikit-learn's contract without importing it, and refuse a split the purge leaves empty rather than skip it. scikit-learn's TimeSeriesSplit cuts rows with a fixed gap and purges no label, so it is not used. The cost is a splitter built once per series, and fewer training bars after each test span, since a piece opens only past the embargo and its warm-up.

**0036 Labels are trades through the same fill model.** A label is what a trade of a stated notional, entered at the next open, would have returned through the same fill model as a backtest, net of fees, funding, spread, slippage and impact, with optional barriers. A short label is computed on its own rather than as the long one's negative, since both pay costs and funding changes sign. A label whose horizon runs past the data is censored even when a barrier was hit first, so censoring never depends on the outcome. Every label carries its end, as the splitters read it, and its average uniqueness. The cost is that labels run the engine, slower than returns read off the closes.

**0037 Indicators run over each instrument's own bars.** `probatum.ta` keeps a closed set of indicators and states each one's convention where implementations differ. Every function returns one value per bar with the warm-up as NaN, crossings return booleans that are false during the warm-up, and a shift pads rather than wraps. A function takes a series `(T,)` or a universe `(T, N)` and computes each column over its own values, carrying across a bar an instrument did not print, so a closure neither breaks an indicator nor restarts it. Every prefix of a series gives the first rows of the whole, to the bit, and the recursive smoothers are vectorized, within rounding of a per-bar loop. The cost is that an indicator outside the set is the user's to write, and that a read by row offset in `next` can land on a row an instrument did not print, where `shift` reads its own last bar.

**0038 The environment shows the agent its account.** `probatum.env` is a Gymnasium vector environment over the Rust batch, with all three of Gymnasium's autoreset modes and Gymnasium's default, `NEXT_STEP`, as its own; the Stable-Baselines3 adapter switches to `SAME_STEP`, which SB3 expects. Every observation carries the account, its weights, unrealized PnL and margin, so an agent sees what it holds, and actions are normalised by gross exposure, so an untrained policy over many instruments cannot ask for many times its leverage. Order actions are decoded in Rust, the reward is floored so a liquidation is a large finite penalty, and each environment draws its episodes from a stream of its own, so an episode can be found again and run as a backtest. The cost is an observation larger than the market data alone.

**0039 An agent carries the spec it trained with.** An agent is judged fairly only if it sees in a backtest what it saw in training, so `probatum.env` records its settings as a versioned JSON spec: the instrument each slot trades, the training span, the venue and, with `normalise=True`, each feature's mean and deviation. A custom function is never pickled. The spec holds a hash of its output on probe bars built the same way on every machine, and a function passed again whose output differs is refused. The spec travels with the agent: `probatum.sb3.wrap` puts it where SB3 saves the model, and `probatum.save` writes it beside a torch module's state dict. `backtest` rebuilds the observation from the spec, runs the agent as one environment, and refuses a Data of other instruments. The cost is that a custom feature function has to be passed again at every backtest, and that a change to it the probe bars never reach passes the check.

**0040 One output buffer, and a path to the GPU.** The batch fills one writable float32 buffer in place, which every framework reaches by its own zero-copy path, and hands observations out as copies by default, so a replay buffer stays safe. `TensorEnv` hands observations, rewards and flags out as tensors on a device through pinned buffers that never block the host, and its resident mode builds each window on the device from the market copied there once, to the bit of the host's. The environments step on threads of their own, as many as their work pays for. Engines, batches and environments clone, sharing the bars and copying everything else, and an engine or a batch pickles between processes of one version. `record="transitions"` keeps one row a step for offline learning, exported as one Arrow IPC file. The cost is a second code path for the device, held bit for bit to the host's, and two observations kept for every transition.

**0041 A run shows as its data.** Every table, statistic record and summary shows, in a notebook and as text, as pandas frames of the data it holds, with no sentence of its own, and a value it has none of shows as none, with its reason. probatum draws no static figure and writes no report: a tear sheet would redraw what the frames hold, so a picture of a run other than the chart is the reader's, made with the plotting they already use. The cost is that such a plot is a few lines of the reader's own, and that a frame needs pandas, without which a table or a record shows its fields.

**0042 The interactive chart is the one picture probatum draws.** The candle chart is kept for reading a run bar by bar. It is built in Python into one self-contained HTML document with its renderer vendored, so a saved chart works offline. It draws arrays that arrive computed and knows no indicator names, and Python and JavaScript meet at one spec, with the JavaScript computing geometry and never policy. The renderer's notice and a link to TradingView sit in its footer, as its licence asks. The cost is a JavaScript renderer kept beside the Python, and a saved chart as large as the bars it holds.

**0043 The maths is verified inside the repository.** No live venue checks it, so every rule is written in the Specification with an equation and a worked example before it is coded, and every worked example is a test. A reference simulator, written from the Specification and never from the engine, solves the liquidation path by bisection where the engine solves it in closed form, and the two are compared on every ledger column, fill and round trip over random cases. Tests are named for the claims they prove, and every example in the documentation parses and names real keywords. The cost is a second simulator maintained beside the engine.

**0044 The core depends on numpy alone.** Everything else is imported when used, so a backtest loads Gymnasium only to run an agent. Two extras cover probatum's own optional features, and frameworks the user brings, such as torch, are never extras, because an extra would install a build over the one the user chose. Python and numpy follow Scientific Python's SPEC 0, dependencies carry no upper bounds, and wheels ship for Linux on x86_64 and ARM, macOS on Apple silicon and Windows. The package declares its own licence beside those of the chart's renderer, its icons and the Rust numpy crate it is built with. The cost is that an older Python or an Intel Mac is not supported, and a Linux older than glibc 2.28 builds the source archive, which needs Rust.

**0045 A strategy is judged at the size and the costs it would trade.** `capacity` runs a policy again at several balances, and `cost_curve` at several multiples of every cost its venue charges for trading, the fees, spread, slippage and impact together, since a sweep of the fee alone leaves out most of what a venue charges. Each level records the return, the Sharpe, the turnover and the round-trip cost the run paid, in basis points of the notional its fills traded. `breakeven_bps` bisects the multiple at which the return reaches zero and gives the round-trip cost paid there. A rebate, funding and the liquidity budget are not moved, being the venue's rates and limits rather than charges for trading. The cost is that a multiple of a venue's costs is not a venue anyone quotes, so the round-trip cost is measured from each run rather than set.

**0046 A Study is kept on disk, and a search resumes from it.** `study.save(path)` writes a Study as a directory of open files, as a Result is written (0026), and `Study.load(path)` reads it back with every table and statistic. `search(..., storage=path)` keeps its Study there as it runs, and the same call made again resumes it: each stored trial is taken in its turn rather than run, so the samplers stand where they stood, and only the trials not stored run, so the Study is the one a search that never stopped returns. A directory holding another search is refused, and a look at the holdout is counted in every directory that holds its search, so no reload or resume loses one. The cost is a directory that grows with each batch until the search ends, and a TPE search that resumes only on the machine and with the number of workers it ran with (0032).

**0047 A search's parameter importance is the share of its scores each parameter explains alone.** `importance()` groups a search's complete trials by each parameter's value and gives the share of the scores' variation the groups' means explain, eta squared, beside the share a parameter with no effect explains by chance. It reads the trials table alone, so it needs neither Optuna's study nor a model fitted to the trials, and it is the same in every process and after a load. The cost is that an effect that shows only in a pair of parameters is missed, and that a sampler which crowds its trials near its winner, as TPE does, makes the importances describe where it searched more than the ground.

**0048 The presets read their instruments from exchange-router.** The builder takes each venue's instruments, with each one's tick, lot and tier table, from exchange-router, the library probatum's bars come from, so each venue's API is read by one adapter, tested against that venue, rather than by a second reader kept in probatum. A preset lists every instrument the router lists, keyed by the symbol its bars carry, at the venue's base rates. The router tells no asset class or zone apart, so a zone with rates of its own, such as Bybit's Innovation Zone, is named in the Venue Notes and set with `replace` by whoever trades it. The fee rates, the liquidation models and Hyperliquid's price and maintenance rules are the venues' documented ones, written in the builder. The cost is that a preset holds only what the router serves, and that an instrument in such a zone pays the base rates until its own are set. Binance's API gives a perpetual's leverage brackets only to a signed-in account, so the router serves none and Binance has no perpetual preset.
